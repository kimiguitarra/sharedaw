# 共同制作用 軽量DAW — MVP仕様書

> このドキュメントは Claude Code に実装を依頼するための仕様書です。
> ここに書かれた内容はオーナー（Kimitake）との検討で**確定済み**の事項です。
> 「未決事項」に挙げたもの以外は、勝手に変更せず、変更が必要と判断した場合はオーナーに確認してください。
> アプリ名は「ShareDAW」に決定（§11）。

---

## 1. 概要

### 1.1 目的
友人と楽曲を共同制作するための、**アイデア出しとラフ録音に特化した軽量DAW**。
本格的なレコーディング・ミックスは Cubase 等の既存DAWで行う。本アプリはその手前の工程を担う。

### 1.2 利用シーン
- Discord で通話しながら、1人が画面共有して同じ画面を見て作業する。
- 各自が作業するときはローカルで作業する。
- 全員が同じ ShareDAW を使い、**プロジェクト単位でクラウド上のバージョン管理により同期**する。
- 取り込み（pull）時もアップロード（push）時も、**DAW上で差分を確認してから**実行する。

### 1.3 利用者・環境
- 利用者：オーナーと友人（少人数）。当面は**無料・非商用**。出来が良ければ将来販売を検討する。
- OS：**オーナーは Windows、友人は Mac**。最初から両OSで同じように動くことを前提に設計する（§8）。

### 1.4 非目標（やらないこと）
- 本格的なミックス・マスタリング機能
- リアルタイム同時編集（Google Docs 的な同時編集）
- Web版・ブラウザ動作（レイテンシの観点からネイティブアプリのみとする）
- ノート単位の自動マージ（競合はトラック単位で利用者が採用する版を選ぶ）

## 2. 技術スタック

| 領域 | 採用技術 | 備考 |
|---|---|---|
| デスクトップアプリ | C++20 / **JUCE** | Win・Mac ネイティブ |
| オーディオエンジン | **Tracktion Engine** | トラック、クリップ、MIDI、テンポマップ、プラグインホスト、録音、レンダリングを利用 |
| 内蔵音源 | **sfizz**（SFZプレイヤー）＋ SFZ形式のサンプル音源 | Tracktion の内部プラグインとして組み込む |
| ビルド | CMake（JUCE / Tracktion Engine / sfizz は git submodule または FetchContent） | Windows は Visual Studio 2022 |
| CI | GitHub Actions（Windows ランナー＋macOS ランナー） | Mac 実機がなくても Mac 版をビルドするため |
| 同期サーバー | **Cloudflare Workers**（TypeScript）＋ **R2** ＋ **D1** | §6 |
| ライセンス | 当面は GPL（JUCE / Tracktion Engine の GPL 版） | 販売時に商用ライセンスへの切り替えを検討する。コード構成は切り替え可能にしておく |

### 2.1 アーキテクチャ上の重要な決定
- **正（source of truth）は独自のプロジェクトJSON**（§7）。Tracktion Engine の Edit は、そのJSONから構築する実行時の表現として扱う。
  - JSON → Edit の変換層と、Edit上の編集 → JSON への反映層を用意する。
  - 同期・差分・保存はすべて JSON 基準で行う。Tracktion の Edit ファイル形式を同期フォーマットにしない。
- リポジトリ構成（案）：
  ```
  /app      JUCE + Tracktion Engine のデスクトップアプリ
  /server   Cloudflare Workers（API）、D1マイグレーション
  /shared   プロジェクトJSONのJSON Schema、差分仕様、テスト用フィクスチャ
  /assets   内蔵音源（SFZ + サンプル）
  /docs     本仕様書など
  ```

## 3. 機能要件（MVP）

### 3.1 トラック種別

| 種別 | 内容 |
|---|---|
| MIDIトラック | 内蔵音源（ドラム / ベース / ピアノ）、または外部プラグインを発音源にする |
| オーディオトラック | 録音・読み込みしたオーディオ、およびバウンス結果を置く |
| コードトラック | プロジェクトに1本。§3.8 |
| テンポトラック | プロジェクトに1本。§3.9 |
| 拍子トラック | プロジェクトに1本。§3.9 |

### 3.2 MIDI編集
- ピアノロールで自由に打ち込み・編集できる（追加、削除、移動、長さ変更、ベロシティ）。
- **ピッチベンド**：MIDI クリップごとに `pitchBends`（`[クリップ先頭からの tick, 値 -8192〜8191（0 が中央）]` の並び）を持つ。
  ピアノロールの下の段を「ピッチベンド」に切り替えて、ドラッグで描く（Alt か右ボタンで中央に戻す、ダブルクリックで全部消す）。
  キーボードのピッチホイールも録音する。クリップの頭と終わりでは中央に戻す（前後の音に残さない）。MIDI ファイルの読み書きにも入る。
- グリッドへのスナップ（1/1〜1/32、3連符）とクオンタイズ。
- ドラムトラックはGMドラムマップで表示する（ノート名をドラムパーツ名で表示）。

### 3.3 内蔵音源
- **ドラム・ベース・ピアノの3種**を用意し、SFZ形式で sfizz により鳴らす。
- 「音源の調整」は**パラメータとして JSON に保持**し、差分表示できるようにする。例：
  - ドラム：パーツごとのサンプル差し替え（例：スネアを別キットのものに替える）、パーツごとの音量・パン・チューニング
  - 全音源共通：音量、パン、簡易なトーン調整
- 内蔵音源は**バージョン番号付きで固定配布**し、プロジェクトには使用した音源のIDとバージョンを記録する。Win と Mac で必ず同じ音が鳴るようにするため。
- 内蔵音源のトラックは両OSで同じ音が再現できるので、**バウンス不要**で同期できる。
- 素材のライセンスは **CC0 または CC-BY のものに限定**する。将来販売しても差し替えずに済むようにするため。CC-BYのクレジットはアプリ内に表示する。
  - ピアノ：Salamander Grand Piano（CC-BY）を第一候補とする。
  - ドラム：CC0 または CC-BY のフリーキットから選定する（§11）。1.2.0 のキットは PopAcoustic（Big Rusty Drums）・JazzAcoustic（Virtuosity Drums、どちらも CC0）・Electronic。
    キットの名前を変えたときは、マニフェストの `kitAliases` で前の版の名前（acoustic など）を新しい名前に読み替える。
  - ベース：3.0.0 から録音された実際のベースのサンプル（Karoryfer Samples の Growlybass・Meatbass、CC0）。低い E を MIDI 28（E1）に割り当てる（§11）。
    3.2.0 は弾いた瞬間だけ高く揺れる音程を、落ち着いた高さにそろえ（時間軸を伸び縮みして読み直す）、アタックを和らげたもの。
  - サンプルの頭の無音は詰めるか `offset=` で飛ばし、ノートの位置で鳴るようにする（ピアノ 1.1.0、ドラムの JazzAcoustic）。

### 3.4 外部プラグイン
- 対応形式：**VST3（Win / Mac）**、**AU（Mac のみ）**。
- 各自が持っているプラグインをローカルで自由に使える。
- **プラグインのスキャンは別プロセスで行う**。スキャン中にクラッシュしたプラグインは自動的にブラックリストに登録し、以後は読み込まない。
- 再生時のプラグインは DAW と同じプロセスで動かす（完全なサンドボックス化は MVP では行わない）。クラッシュ対策は自動保存で行う（§3.10）。

### 3.5 録音
- オーディオドライバ：Windows は **ASIO**（ASIO が使えない環境向けに WASAPI も選べるようにする）、Mac は **CoreAudio**。
- 設定画面で入出力デバイス、バッファサイズ、サンプルレートを確認・変更できる。
- **レイテンシ補正**：ドライバが報告する入出力レイテンシで補正する。加えて、デバイスごとの手動オフセット（サンプル単位）を設定できるようにする。
- 入力モニタリング：オーディオインターフェースのダイレクトモニタリングを推奨する。ソフトウェアモニタリングはトラックごとにオン・オフできる。
- 録音中はメトロノームを鳴らせる（音量と、カウントイン1〜2小節の設定あり）。
- 録音データは録音確定時に 48kHz / 32bit float WAV として保存し、ハッシュ名に変換する（§7.3）。

### 3.6 オーディオ編集（非破壊）
- 対応する操作：**分割、トリム（開始・終了位置の調整）、移動、削除、クリップ音量、フェードイン・アウト**。
- すべて**非破壊**で行う。元ファイルは一切書き換えない。クリップは「元ファイルのハッシュ＋元ファイル内のオフセット＋長さ」の参照として持つ。
- 外部のWAVやAIFFを読み込むと、プロジェクトのフォーマット（48kHz / 32bit float WAV）へ自動変換する。

### 3.7 バウンス（パラ書き出し）
- トラック単位でバウンスできる。範囲はプロジェクトの先頭から末尾まで、プラグインの残響を考慮して末尾に余白（デフォルト2秒）を付ける。形式は 48kHz / 32bit float WAV。
- バウンスすると（Cubase のインプレイスレンダリングと同じく）**元のトラックのすぐ下にオーディオトラック「元の名前（バウンス）」ができる**。
  - 音量・パン・EQ・コンプ・出力先・センドは元のトラックと同じにする（バウンスの音はそれらを通す前の音）。
  - もう一度バウンスすると、同じオーディオトラックのクリップを差し替える。
  - バウンスしたトラックは、クリップが元のトラックの `render.audioHash` の音を使うことで見分ける（JSON に新しい項目は足さない）。
  - 内蔵音源のトラックをバウンスしたときは、元のトラックをミュートする（二重に鳴らないように）。
- **外部プラグインを使うトラックはサーバーにアップしない（この PC だけ）**。他の人の PC では鳴らせないため、代わりにバウンスしたオーディオトラックだけをアップする。
  - 持ち主の PC（プラグインの状態ファイルがある）では、外部プラグインのトラックをそのまま鳴らして編集し、バウンスしたトラックは表示も再生もしない。
    バウンスしたトラックの音量・パンなどは、アップの前に元のトラックに合わせる。
  - 同期パネルでは「この PC だけ」と表示し、アップのチェックは付けられない。ダウンロードしてもそのまま残る。
  - 以前の版でアップ済みの外部プラグインのトラックも、持ち主が次にアップしたときにサーバーから消える（他の人の PC からはダウンロードで消える）。
- アップするとき、まだバウンスしていない・バウンスの後に変わった外部プラグインのトラックがあれば、「バウンスしてアップ / バウンスせずにアップ / キャンセル」を聞く（ワンアクションでバウンスとアップ）。

### 3.8 コードトラック（Cubase のコードトラック準拠）

#### 入力方法
- プロジェクトにコードトラックを1本立ち上げ、**任意の拍の位置にコードイベントを打ち込む**。Cubase のコードトラックと同様の操作にする。
  - 鉛筆ツールでクリックすると、その位置にコードイベントを作成する（グリッドスナップあり、デフォルトは1拍）。
  - イベントはドラッグで移動、削除キーで削除できる。
  - イベントをダブルクリックすると**コードエディタ**が開く：
    - ルート、コードタイプ、テンション、ベース音（分数コード）をボタンで選べる。
    - **テキスト入力欄**も備え、`G7(9,13)` のように打てばパースして反映する。
  - **「X」（ノーコード）イベント**を置けて、その区間は発音しない。
- 各コードイベントは**次のイベントまで持続**する。最後のイベントはプロジェクトの末尾まで持続する。
- コードトラック上に、コードネームを見やすく表示する。

#### 対応するコード表記
- ルート：C〜B、`#` / `b`（`♯` / `♭` も受け付ける）
- コードタイプ：
  - 三和音：メジャー、`m`、`dim`、`aug`（`+`）、`sus2`、`sus4`
  - 四和音：`6`、`m6`、`7`、`M7`（`maj7`、`△7` も可）、`m7`、`mM7`、`m7-5`（`m7(b5)`、`ø` も可）、`dim7`、`7sus4`
  - `add9`
- テンション：`9`、`b9`、`#9`、`11`、`#11`、`13`、`b13`。括弧表記 `(9,13)` と連結表記 `9`、`13`（例：`C9`、`Am11`）の両方に対応する。
- **分数コード**：`C/E`、`F/G`、`Am7/G` など。ベース音がコードの構成音でない場合も対応する。
- パーサーは表記の揺れを正規化し、内部では構造化データ（root、quality、tensions[]、bass）として保持する。
- 同じ表記のパースは、将来の別アプリ（コード進行メモアプリ）でも使い回せるよう、独立したモジュールにしておく（C++ ライブラリとして分離）。

#### 自動発音（ボイシング）
- コードトラックには専用の発音先（内蔵ピアノ）がある。ミュート（M）と音量（ミキサー）を調整できる。
- 一括入力：範囲と間隔を指定して空のコードをまとめて置き、ディグリーの数字（例: 1625）を前から順に入れる。
  コードを選んで数字 1〜7 を打つと、キーの四和音が入って次のコードへ進む。
- **コードイベントごとに 1 回だけ鳴らす**（Cubase と同じ）：次のコードイベントまで、ただし最長 1 小節。弾き直しはしない。空のコード（未入力）とノーコード（X）は鳴らさない。ベロシティは固定（デフォルト80）。
- **ボイシングは自動で最適化**する（ルールベース）：
  1. **ベース（左手）**：分数コードなら分母の音、それ以外はルート。音域は MIDI 36〜47（C2〜B2）。
  2. **上声部（右手）**：3〜4音。音域は MIDI 52〜76（E3〜E5）。
  3. **音の優先度**：3度と7度（6度）とテンションを優先する。音数が多すぎる場合は、5度→ルートの順に省く（ルートはベースが担うため）。
  4. **ボイスリーディング**：候補となる全転回形・配置を列挙し、「前のコードの上声部からの移動量の合計」が最小のものを選ぶ。最初のコードは上声部の中心が MIDI 64 付近になるものを選ぶ。
  5. **濁り回避**：MIDI 60 未満で隣り合う声部の間隔が短3度未満になる配置は減点または除外する。上声部とベースが近すぎる配置（間隔が長3度未満）も除外する。
  6. **例外**：`b9` は、ルートの長7度上にぶつかる配置を避けるなど、基本的な回避ルールを実装する。
- 将来の拡張（MVP外）として、コードトラックの発音を通常の MIDI トラックに書き出す「MIDI化」を想定する。

### 3.9 テンポトラック・拍子トラック
- **テンポトラック**：任意の小節・拍でテンポ変更イベントを置ける（MVP は階段状の変化のみ。徐々に変化するテンポはなし）。初期値は120 BPM。
- **拍子トラック**：任意の小節頭で拍子変更イベントを置ける（例：4/4、3/4、6/8、5/4、7/8）。
- MIDI ノート、コードイベント、オーディオクリップの**開始位置**は、音楽的な時間（tick）で持つ。そのため、テンポが変わっても小節上の位置は保たれる。
- **オーディオはテンポに追従しない**（タイムストレッチしない）。テンポを変更するとオーディオの中身がずれることを UI で注意表示する。

### 3.10 保存・自動保存・クラッシュ復旧
- 手動保存（Ctrl/Cmd+S）に加え、**自動保存**を行う（デフォルト1分ごと、かつ主要な編集操作の後）。
- 起動時に前回が異常終了だったことを検知し、自動保存から復旧するか確認する。

### 3.10b 楽曲を選ぶ画面
- 起動時に「楽曲を選ぶ」画面を出す（曲は基本的にサーバーで管理し、この PC にはダウンロードしたフォルダを置く）。
- この PC の曲: 開いた・保存した・ダウンロードしたフォルダを覚えておき、ダウンロード先のフォルダの中も探す。
  各フォルダの `.collab/meta.json`（ベースリビジョン）と `base.json` との差分から、未 push の変更の有無と中身を出す。
- サーバーの曲: `GET /projects`（最新リビジョンの番号・日時・作者を含む）。プロジェクト ID で突き合わせる。
- 状況: 最新 / 未送信の変更あり / サーバーに新しい版 / 両方に変更 / サーバーだけ / この PC だけ / サーバー未確認 / 別のサーバー / サーバーに見当たらない。

### 3.11 その他 UI
- UI 言語は日本語。
- トランスポート：再生、停止、録音、ループ範囲、メトロノーム、小節・拍とタイムの表示。
- ミキサー（F3）：Cubase の MixConsole に寄せる。ストリップごとに出力先、インサート、EQ（小さなカーブ）、コンプ（ゲインリダクション）、
  センド、パン、音量フェーダー（目盛り付き）、レベルメーター、ミュート、ソロ、番号と色付きの名前。
  音量・パン・センドは数値でも入力できる。左端に入力（オーディオ機器の入力チャンネルごとのレベル）、
  右端にメトロノームとマスターを固定し、トラックだけを横にスクロールする。F3 か右下のボタンで全画面に開く。
  フェーダーはキャップ付きで、つかんだ所から動かす。メーターはフェーダーと同じ目盛りで、0 dB の線・0 dB から上の赤い帯・
  -12 dB から上の黄色を持ち、上に直近 3 秒の最大値を数字で出す（0 dB 超は赤、クリックで戻す）。
- インスペクター（画面の左、Alt+I）：選択中のトラックの入出力（入力・出力とそれぞれのモノ / ステレオ）、音源、チャンネルストリップ。
  トラックヘッダーは名前と録音待機・ミュート・ソロだけ。
- **トラックの入出力のチャンネル**：プロジェクト JSON のトラックに `inputChannels`（audio のみ）と `outputChannels`（1 = モノ、2 = ステレオ。
  2 のときは省略）。ステレオの入力は隣り合う 2 つのモノの入力で録り、取り込むときに 1 つのステレオの WAV にする。
  出力がモノのトラックは、チャンネルストリップの後で左右を混ぜてからパンで振る。
- **重なったオーディオクリップ**：後ろ（新しい）のクリップが上になり、重なった所は上だけが鳴る（Pro Tools と同じ。データは消さない）。
  切り替わりはクロスフェード（下のクリップを延ばして重ねる）。長さと形はオーディオトラックの `crossfade`（`ms`・`shape` = equalPower / linear / sCurve。
  10 ms・等パワーのときは省略）。
- **内蔵エフェクト**：エフェクトに `builtin`（busComp / saturator / roomReverb / hallReverb / plateReverb）と `params`（数値の辞書）を持つ
  （外部プラグインの `plugin` の代わり）。信号処理は collab_core（JUCE に依存しない）にあり、誰の環境でも同じに鳴るのでバウンスは不要。
- **キートラック**：プロジェクト JSON の `keyTrack`（`id` はプロジェクト ID から決まる。空なら省略）に、
  小節の頭のキー（`bar`・`tonic` = 主音のピッチクラス 0〜11・`mode` = major / minor）を持つ。差分は独立したスコープ。
  コードのディグリー表示とディグリー入力（数字・ローマ数字、臨時記号 b / #、分数のベースもディグリーで可）の基準になる。
  ディグリーはキーの音階（マイナーはナチュラルマイナー）を基準にし、外れた音は ♭ / ♯ を付ける。
- **マスター**：プロジェクト JSON の `master`（`id` はプロジェクト ID から決まる。既定値のときは省略）に
  リミッター（`enabled`・`thresholdDb`・`ceilingDb`・`character`・`mode` = analog / tube / modern）と、
  インサートの `effects`（トラックのエフェクトと同じ形。リミッターの前に挿す。ミキサーのマスターのストリップから追加）を持つ。
  外部プラグインはその PC にあるときだけ鳴る（ない PC では飛ばす）。
  差分はテンポなどと同じく独立したスコープ。曲の音は内部のミックスバスに集まり、リミッターとラウドネス計測
  （BS.1770 の K 特性、100 ms ブロック、-70 LUFS と -10 LU のゲート）を通ってから出力される。メトロノームは通さない。
- **ミックスダウン**：曲の先頭から最後（＋余韻。最低 2 秒）を 48 kHz / 24 bit WAV、または 44.1 kHz / 320 kbps MP3（LAME）に書き出す。リミッターを含む。
- **パラデータ**：トラックごとに 48 kHz / 24 bit WAV（全部同じ長さ）。インサート・EQ・Comp・音量・パンを含み、センド・バス・マスターは通さない。ミュート中のトラックとバスは書かない。
- **MIDI ファイル**：SMF タイプ 1（960 PPQ）。MIDI トラック・コードトラック（Chords）・テンポ・拍子・キー・マーカー。
- マスターのリミッターは先読み分（約 1.5 ms）遅れる。切っているときも同じだけ遅らせる（報告する遅れと合わせ、ミックス全体が早く出ないように）。
- **バストラック**：`type: "bus"` のトラック（クリップを持たない）。各トラックの `output` にバスの ID を入れるとその
  バスへ出力し（空ならマスター）、`sends`（送り先のバス・量・プリ/ポスト）で一部を送る。ループになる出力先は選べない。
- **チャンネルストリップ**：全トラックに EQ（ローカット、ハイカット、Low シェルフ、Low Mid / Mid ピーキング、High シェルフ。
  スペクトラムの上でカーブを操作するグラフィカル EQ）とコンプ
  （FET / Optical を選択。どちらにも検出側だけに効くハイパス「LOW THRU」`comp.sidechainHpHz`、0 = オフ）を標準装備する。
  音源・エフェクトの後、音量・パンの前にかかる。EQ とコンプの順番は `order`（`eqComp` 既定 / `compEq`）で入れ替えられる。
  プロジェクト JSON の `strip` に保存し（既定値のときは省略。`order` と `sidechainHpHz` も既定値なら書かない）、
  バウンスには含めない（フィンガープリントにも含めない）。EQ とコンプは別々の画面で編集する。
- 操作は Cubase に寄せる（選択・鉛筆ツール、クオンタイズ値と J のスナップ切り替え、F の自動スクロール、P でループ範囲など）。
  Studio One モードは当面 Cubase と同じ操作で、利用者のレビュー後に作り込む。
- Discord での画面共有を想定し、**文字サイズの拡大設定**を用意する（共有画面でも読めるように）。

## 4. 同期・バージョン管理の概念

### 4.1 用語
- **プロジェクト**：1曲分の作業単位。サーバー上で一意の ID を持つ。
- **リビジョン**：プロジェクトの確定版スナップショット。連番（1, 2, 3, …）で、親リビジョン、作成者、コメント、日時を持つ。
- **ヘッド**：サーバー上の最新リビジョン。
- **ベース**：ローカルの作業が基にしているリビジョン。
- **スコープ**：差分と採用の単位。トラック 1 本、またはテンポ・拍子・コード・マーカー・キー・マスター。

### 4.2 ロックは使わない
- ロック（編集権）は使わない。誰でもどのトラックでも編集してアップできる。
- 同時に同じスコープを変えた場合は**競合**として扱い、利用者がスコープごとに採用する版を選ぶ（§4.5）。
  更新日時だけで新しい方を採用することはしない（後から保存した方が、先にアップされた他の人の変更を消してしまうため）。

### 4.3 差分の種類（差分表示の対象）
すべての要素は固有のID（UUID）を持ち、**ID基準で差分を取る**。

| 分類 | 例 |
|---|---|
| トラック | 追加、削除、名前・色の変更、音量・パン・ミュート |
| 音源の調整 | 内蔵音源のパラメータ変更（スネアのサンプル差し替え、パーツ音量など）、外部プラグインの差し替え |
| MIDIノート | 追加、削除、移動、長さ・ベロシティの変更、ピッチベンド |
| オーディオクリップ | 追加、削除、移動、分割、トリム、クリップ音量、フェード |
| バウンス | レンダー済みオーディオの更新 |
| コード | コードイベントの追加、削除、移動、変更 |
| テンポ・拍子 | イベントの追加、削除、変更 |

### 4.4 同期パネル（§4.5, 4.6 の UI）
- 右側のパネルに、プロジェクトの**すべてのトラック**（と、テンポ・拍子などのスコープ）を「名前 | ダウンロード | アップロード」の表にする。
  パネルは右端の細い帯に畳める（«/»）。畳んでもダウンロード・アップロード・競合の数を色分けして出す。
- 各行の状態（ベース・ローカル・ヘッドをスコープ単位で比べる）:
  - **この PC で変更**：アップロードの欄に自動でチェック。チェックしたものだけをアップする。
  - **サーバーで更新**（他の人がアップした）：行とトラックヘッダーを青くし、ダウンロードの欄に自動でチェック。外すと今のまま。
  - **競合**（両方で変更され、内容が違う）：行とトラックヘッダーを橙にする。トラックは両方の欄にチェック（= 両方残す）。
    ダウンロードだけならサーバーの版、アップロードだけなら自分の版。トラック以外はどちらか一方を選ぶまでダウンロードできない。
  - 変更なし：薄く表示する（チェックの欄は使えない）。
- アップ時のコメントの入力はしない。
- 行をクリックすると、その行の「この PC の変更」と「サーバーの変更」を並べて表示する（何小節目の何が変わったか）。項目を選ぶとタイムラインのその場所へジャンプする。
- サーバーは定期的（20 秒ごと）に確認し、他の人がアップしたら右下にお知らせを出す。競合がないときは自動でダウンロードする設定もできる（再生・録音中は行わない）。
- リビジョン番号・履歴・ロックはパネルに出さない（履歴はメニューから見られる）。

### 4.5 ダウンロード（取り込み）の動作
- ヘッドを基に、スコープごとに次の版を採用する：
  - 自分だけが変えたスコープ：ローカル
  - サーバーだけが変えたスコープ：ヘッド（ダウンロードのチェックを外したらローカル。次のアップでサーバーの変更を戻すことになる）
  - 競合：利用者が選んだ版（「両方」ならヘッドの版に加えて、ローカルの版を「（自分の版）」という別のトラックとして残す）
- 取り込む前のローカルは `.collab/before-download/` に保存してから反映する（データを失わない）。
- 取り込み後、ベースをヘッドのリビジョンに更新する。

### 4.6 アップの動作
1. ベース ≠ ヘッドなら、先にダウンロードする（パネルでの選択を使う。サーバー側でも親リビジョン＝ヘッドを検証し、違えば 409）。
2. アップする内容 = ベース（= ヘッド）に、チェックしたスコープだけローカルの内容を入れたもの。チェックを外したものはこの PC にだけ残る。
3. 外部プラグインを使うトラックはアップしない。バウンスしていない・古いものがあれば、その場でバウンスするか聞く（§3.7）。
4. 新規のオーディオファイルについて、サーバーに存在しないものだけをアップロードする（§6.4）。
5. プロジェクト JSON をアップロードし、新しいリビジョンとして登録する（アプリからはコメントなし。API はコメントも受け付ける）。

## 6. 同期サーバー（Cloudflare）

### 6.1 位置づけ
- 既存の疑似Google Drive（正式データの置き場）とは**完全に別の、作業スペース専用**の Cloudflare 環境（別の R2 バケット、D1 データベース、Worker）を用意する。

### 6.2 認証
- 利用者は少人数なので、**ユーザーごとの API トークン方式**とする。
  - トークンはオーナーが管理用スクリプト（wrangler 経由）で発行し、友人に渡す。
  - D1 にはトークンのハッシュのみを保存する。
  - アプリは初回起動時にサーバー URL とトークンを入力する。トークンは OS の資格情報ストア（Windows Credential Manager / macOS Keychain）に保存する。
- すべての API は `Authorization: Bearer <token>` で呼ぶ。

### 6.3 D1 スキーマ（案）
```sql
users(
  id TEXT PRIMARY KEY, display_name TEXT NOT NULL,
  token_hash TEXT NOT NULL, created_at TEXT NOT NULL
)
projects(
  id TEXT PRIMARY KEY, name TEXT NOT NULL,
  head_revision INTEGER NOT NULL DEFAULT 0,
  created_by TEXT NOT NULL, created_at TEXT NOT NULL
)
project_members(
  project_id TEXT, user_id TEXT, PRIMARY KEY(project_id, user_id)
)
revisions(
  project_id TEXT, number INTEGER, parent_number INTEGER,
  author_id TEXT, message TEXT, project_json_hash TEXT NOT NULL,
  created_at TEXT NOT NULL, PRIMARY KEY(project_id, number)
)
locks(
  project_id TEXT, track_id TEXT, user_id TEXT, acquired_at TEXT,
  PRIMARY KEY(project_id, track_id)
)
lock_events(
  id INTEGER PRIMARY KEY AUTOINCREMENT, project_id TEXT, track_id TEXT,
  user_id TEXT, action TEXT /* acquire|release|force_release */, created_at TEXT
)
blobs(
  hash TEXT PRIMARY KEY, size INTEGER, created_at TEXT
)
```
- 日時はすべて **UTC の ISO 8601**。

### 6.4 R2 のキー構成
- `blobs/<sha256>`：オーディオ、プロジェクト JSON のスナップショットなど、すべての実体。**コンテンツアドレス方式で、不変・重複なし**。
- 実体をハッシュ名で1か所に置くため、同じファイルは二重に保存されない。

### 6.5 API（案）
| メソッド・パス | 内容 |
|---|---|
| `GET /projects` | 参加しているプロジェクトの一覧 |
| `POST /projects` | プロジェクトの新規作成（最初のリビジョンは push で作る） |
| `GET /projects/:id` | プロジェクトの情報（ヘッドのリビジョン番号を含む） |
| `PATCH /projects/:id` | 曲名を変える `{name}` |
| `DELETE /projects/:id` | 曲を削除する（参加している人なら誰でも）。リビジョン・ロック・メンバーと、その曲だけが使っていたプロジェクト JSON の実体を消す（オーディオの実体は共有されうるので残す） |
| `DELETE /projects/:id/members/me` | 参加をやめる（作った人以外） |
| `GET /projects/:id/revisions` | リビジョン履歴（番号、作成者、コメント、日時） |
| `GET /projects/:id/revisions/:n` | 指定リビジョンの project JSON のハッシュとダウンロード URL |
| `POST /blobs/check` | `{hashes: [...]}` を受け取り、サーバーに存在しないハッシュと、そのアップロード用の署名付き PUT URL を返す |
| `GET /blobs/:hash` | ダウンロード用の署名付き URL を返す |
| `POST /projects/:id/revisions` | `{parentNumber, message, projectJsonHash, changedTrackIds}` を受け取る。サーバーは次を検証する：親＝ヘッド、参照される blob がすべて存在すること。問題なければヘッドを進める。親≠ヘッドなら 409 を返す（ロックは確認しない） |
| `GET /projects/:id/locks` | （旧版との互換用。アプリは使わない）ロックの一覧 |
| `POST /projects/:id/locks` | `{trackId}` のロックを取得する（取得済みなら 409 と保持者を返す） |
| `DELETE /projects/:id/locks/:trackId` | ロックを解除する（`?force=true` で強制解除） |

- アップロードとダウンロードは R2 の**署名付き URL で直接**行い、Worker を経由させない。大きなオーディオでも Worker の制限に当たらないようにするため。
- アップロード完了後、サーバー側でハッシュとサイズを検証し、`blobs` テーブルに登録する。
- リビジョン登録の検証とヘッドの更新は、D1 上でアトミックに行う。

## 7. プロジェクト JSON 仕様

### 7.1 基本方針
- UTF-8 の JSON。先頭に `schemaVersion` を持ち、将来のマイグレーションに備える。
- JSON Schema を `/shared` に置き、アプリとサーバーの両方で検証する。
- **すべての要素（トラック、クリップ、ノート、イベント）は UUID を持つ**。
- **時間の単位**：
  - 音楽的な時間は tick（**PPQ 960**）。MIDI ノート、コード、テンポ、拍子、オーディオクリップの開始位置に使う。
  - オーディオの長さやオフセットはサンプル数（48kHz 基準）。
- プロジェクトの**サンプルレートは 48kHz で固定**。オーディオ実体は **32bit float WAV** に統一する。
- 差分を安定させるため、配列の出力順は決定的にする（ノートは開始 tick → ピッチ → ID の順など）。

### 7.2 構造（概略）
```jsonc
{
  "schemaVersion": 1,
  "projectId": "uuid",
  "name": "曲名",
  "sampleRate": 48000,
  "ppq": 960,
  "tempoTrack":  { "id": "uuid", "events": [ { "id": "uuid", "tick": 0, "bpm": 120.0 } ] },
  "meterTrack":  { "id": "uuid", "events": [ { "id": "uuid", "bar": 1, "numerator": 4, "denominator": 4 } ] },
  "chordTrack":  {
    "id": "uuid",

  },

    {
      "id": "uuid", "type": "midi", "name": "Drums", "color": "#E57373",

        "kind": "builtin",
        "id": "builtin.drums", "version": "1.0.0",

      },
      "clips": [
        { "id": "uuid", "startTick": 0, "lengthTick": 15360,

      },
```

- 外部プラグインの状態（`stateRef`）は持ち主の環境専用。他の環境では参照するだけで、使用しない。

### 7.3 オーディオ実体
- 録音、読み込み、バウンスの結果を 48kHz / 32bit float WAV に変換し、SHA-256 を計算して `audio/<sha256>.wav` に保存する。
- 実体は不変。編集はクリップのパラメータ変更だけで表現する。

## 8. Windows / Mac 互換性の要件

### 8.1 ファイル・データ
- **ファイル名で参照しない**：Mac は日本語ファイル名を NFD（濁点が分解された形）で扱うため、同じ名前でも一致しないことがある。オーディオはハッシュで参照し、表示名は JSON 内に NFC で保存する。
- 文字列の比較や保存の前に Unicode を NFC に正規化する。
- **絶対パスを持たない**。相対パスのみ、区切りは `/`。
- ファイル名には Windows で使えない文字（`\ / : * ? " < > |`）を使わない。大文字・小文字の違いだけで区別しない。
- 日時は UTC で保存する。
- オーディオのフォーマットは 48kHz / 32bit float WAV に固定する（§7.1）。オーディオインターフェースが 44.1kHz で動いている場合も、エンジン側で正しく扱う（プロジェクトのレートは 48kHz 固定で、デバイス側をリサンプリングするか、48kHz への設定を促す）。
- 内蔵音源は、両OSで同一のファイルをバージョン管理して配布する。

### 8.2 プラグイン
- VST3 は両OSで、AU は Mac のみで対応する。
- 同じプラグインでも OS 間で状態の互換性はない前提とする（バウンス必須の方針で吸収する）。

### 8.3 ビルド・配布
- **GitHub Actions で Windows 版と Mac 版を両方ビルド**する。オーナーは Windows しか持っていないため、Mac 版は CI でビルドする。**M1 の段階から CI を整備**し、OS 差の問題を早く見つける。
- Mac 版は **Universal Binary**（Apple Silicon と Intel の両方）にする。
- **Mac のマイク許可**：
  - Info.plist に `NSMicrophoneUsageDescription` を入れる。
  - Hardened Runtime を使う場合は `com.apple.security.device.audio-input` の entitlement も付ける。
  - これがないと、エラーも出ずに無音で録音されるので必須。
- 当面は Apple Developer に登録せず、公証なしで配布する。友人には初回起動の手順（右クリック→開く、または「プライバシーとセキュリティ」での許可）を README に書いて案内する。
- Windows 版は署名なしで配布する（SmartScreen の警告が出る旨を README に記載）。
- 配布物：Windows はインストーラー（またはzip）、Mac は dmg（またはzip）。内蔵音源を同梱する。
- **アプリ内アップデート**：手動の CI ビルドが、アプリのファイルを 1 つずつ同期サーバーに実体（SHA-256）として
  アップロードし、ファイル一覧（マニフェスト）を登録する。アプリは一覧と手元を比べて変わったファイルだけを取得し、
  その場で置き換えて再起動する（Windows は実行中の exe を *.old にずらして置き換え、次の起動で消す）。
  新旧はビルド番号（Actions の実行番号）で判断する。登録は Worker のシークレット `RELEASE_KEY` を持つ CI だけができる。

---

## 9. 非機能要件
- 録音レイテンシ：オーディオインターフェースと ASIO / CoreAudio を使う前提で、バッファ128〜256サンプルで安定して動くこと。
- 軽量であること：内蔵音源を含めたインストールサイズの目安は 1GB 以内。
- データを失わないこと：非破壊編集、実体の不変化、自動保存、pull 時の競合コピーにより担保する。
- 同期の途中で失敗しても、ローカルが壊れないこと：ダウンロードは一時フォルダに行い、検証後に差し替える。

## 11. 決定事項（旧・未決事項）
- アプリ名：**ShareDAW**
- ドラム音源：CC0 または CC-BY のキットから品質で選ぶ（CC0 が扱いやすければ CC0 でよい）
- ベース音源：サンプリングはせず、**ソフトシンセ（sfizz の内蔵オシレーター）**で作る
- Apple Developer 登録（公証）：**しない**。Mac は未署名（アドホック署名）のまま、初回起動の手順を案内する
- 商用ライセンスへの切り替え：**しない**（GPL v3 のまま）
