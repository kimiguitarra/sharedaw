# ShareDAW

友人と楽曲を共同制作するための、アイデア出しとラフ録音に特化した軽量 DAW。
仕様は [docs/spec.md](docs/spec.md)、実装メモは [docs/architecture.md](docs/architecture.md)。

## 進捗

| マイルストーン | 状態 |
|---|---|
| M1 ローカル基盤 | 実装済み |
| M2 録音・編集・プラグイン | 実装済み（実機のオーディオインターフェースでの確認待ち） |
| M3 コードトラック | 実装済み |
| M4 同期 | 実装済み（サーバーは `server/`、手順は [server/README.md](server/README.md)） |
| M5 配布・実運用 | 未着手（本番の内蔵音源・インストーラーは §11 の未決事項） |

### M1 ローカル基盤

- MIDI トラック（内蔵音源: ドラム / ベース / ピアノの仮音源）の追加、名前・色・音量・パン・ミュート・ソロ
- タイムライン: クリップの作成（鉛筆ツールでクリック／ドラッグ）・移動（別トラックへも）・長さ変更・複製・削除
- テンポトラック・拍子トラック・コードトラック（鉛筆ツールでクリックして追加、選択ツールで選択・ドラッグ移動・ダブルクリック編集・Delete 削除、右クリックでメニュー）
- ピアノロール: ノートの追加・削除・移動・長さ変更・範囲選択・移調、ベロシティ、グリッド（1/1〜1/128、3・5・7連符）、
  スナップ、クオンタイズ、ドラムトラックは GM ドラムマップ表示
- 内蔵音源の調整（音量・パン・トーン、ドラムはキット・パーツごとのサンプル差し替え・音量・パン・チューニング）
- 再生・停止・ループ（クリップやノートを選んで P で範囲指定。ルーラーのクリック／ドラッグは再生位置の移動のみ）・メトロノーム・小節.拍.tick と時間の表示
- 保存・読み込み（project.json、JSON Schema で検証）、元に戻す／やり直し、自動保存、異常終了からの復旧
- 文字サイズの拡大（表示 → 文字サイズ、画面共有用）

### M2 録音・編集・プラグイン

- オーディオトラック、オーディオの読み込み（ドラッグ＆ドロップ可。48kHz / 32bit float に変換、SHA-256 のファイル名）
- 録音: オーディオトラックの ● で録音待機、入力（モノラルのチャンネル）の選択、トラックごとのソフトウェアモニタリング、
  R キーまたは ● ボタンで録音・停止。カウントイン（なし / 1 / 2 小節、トランスポートメニュー）はテンポマップどおりに鳴り、
  1 小節目からでも使える
- レイテンシ補正: ドライバが報告する入出力レイテンシで自動補正し、オーディオ設定でデバイスごとに手動オフセット（サンプル）を設定できる
- 非破壊のオーディオ編集: 移動、先頭・末尾のトリム、フェードイン・アウト、クリップ音量、再生位置で分割（Alt+X）
- VST3 / AU のホスト: スキャンは別プロセスで行い、クラッシュしたプラグインはブラックリストに入る（ファイル → プラグイン…）。
  音源・エフェクトとして使え、画面を開ける。状態は `plugins-state/` に保存
- バウンス（トラックを右クリック → バウンス）と「要バウンス」「バウンスが古い」の表示。外部プラグインのトラックは
  バウンスが最新でないと push できない。プラグイン（または持ち主の状態ファイル）がない環境ではバウンスした音で再生する
- Windows は ASIO（ASIO SDK 付きでビルドした場合）と WASAPI、Mac は CoreAudio

### M3 コードトラック

- コードの入力（`CM7(9)`、`Am7/G`、`X` など）、コードレーンでの移動・長さ変更、コード名のエディタ
- 内蔵ピアノでのコード再生（ボイシングは前のコードからの動きが少なくなるように選ぶ）

### M4 同期

- Cloudflare Workers + D1 + R2 のサーバー、トークン認証（OS の資格情報ストアに保存）
- ロックはなし。トラック・テンポ・拍子・コードなどの単位で、ダウンロードした時点（ベース）・この PC・サーバーの 3 つを比べる
  （更新日時ではなく中身で比べるので、両方で変えたところは必ず「競合」になり、どちらを使うかを選ぶ）
- ダウンロード / アップ（アップするものをチェックで選ぶ）、必要なオーディオだけを転送。
  ダウンロード前のこの PC の内容は `.collab/before-download/` に残す

### 操作（Cubase 寄せ）

- 操作モード: 設定 → 操作モード で「Cubase」「Studio One」を選べる。現在 Studio One モードは Cubase と同じ操作
  （`EditorState.h` の `EditBehaviour::forMode()` で後から作り込む予定）
- ツール（Cubase と同じ番号）: 1 選択（標準）/ 2 鉛筆 / 3 はさみ。
  空いている所を右クリックするとツールの切り替え・貼り付け・トラックの追加のメニュー。ヘルプ → 操作とショートカットの一覧（F1）
- クリップ: Ctrl/Shift+クリックで複数選択、空いている所をドラッグで範囲選択、まとめて移動・削除・複製（Ctrl+D）・
  コピー / 切り取り / 貼り付け（Ctrl+C / X / V、再生位置へ）、Ctrl+← / → でずらす。MIDI クリップも左端で長さを変えられる
  （隠れたノートは消えずに残る）。ピアノロールでも Ctrl+C / X / V / D、Shift/Ctrl+↑↓ でオクターブ
- 鉛筆・選択: トランスポートバーのボタンでも切り替えられる。
  鉛筆ではテンポ・拍子・コード・MIDI クリップ・ノートを任意の場所に置いていく（ピアノロールではクリックで追加、
  ドラッグで長さ、既存ノートをクリックで削除）。選択ツールでは選択・移動・長さ変更・範囲選択。
  鉛筆ではマウスの位置に、クリックで置かれる場所（縦線・点線の枠・ノートの影）が出る
- オーディオクリップを選ぶと、下のパネルにそのクリップの波形を拡大してグリッド線と一緒に表示する
  （クリックで再生位置、Ctrl+ホイールでズーム、ホイールで横スクロール）
- マーカー〜コードのレーンの上でも Ctrl+ホイール（ズーム）・Shift+ホイール（横スクロール）が効く。
  横にスクロールしても、画面の左端にその位置のテンポ・拍子・キーを表示し続ける
- 楽曲（起動時に出る。ファイル → 楽曲を選ぶ、Ctrl/Cmd+Shift+O）: Google Drive のように、サーバーにある曲の一覧から開く。
  曲はサーバーで作り（「＋ 新しい曲」）、ダウンロードして編集する（この PC だけにある曲という考え方はない）。
  状況は 最新 / この PC にアップしていない変更 / サーバーに新しい変更 / 両方に変更 / まだダウンロードしていない。
  曲を右クリック（または Delete / F2）で 開く・名前を変更・フォルダを表示・削除。削除・名前の変更は曲のメンバーなら誰でもできる
  （削除は元に戻せない。この PC のフォルダはゴミ箱へ。オーディオの実体は他の曲と共有していることがあるのでサーバーに残る）。
  ダウンロード先は既定で「ドキュメント/ShareDAW」（画面の「変更…」で変えられる）
- 同期パネル（右側）: 「»」で右端の細い帯に畳み、「«」（または帯のどこか・F7）で開く。畳んでいても
  ↓ ダウンロードできる数（青）・↑ アップロードできる数（緑）・! 競合の数（橙）が出る。
  開くと曲の全トラック（とテンポ・拍子・コード・マーカー・キー・マスター）を「トラック | ↓ DL | ↑ UP」の表で並べる。
  他の人がアップして新しくなった行は色が付き DL に自動でチェック（外すと今のまま）、この PC で変えた行は UP に自動でチェック
  （外すと今回はアップしない）。「ダウンロード」「アップロード」でチェックの入ったものだけを送受信する（コメントの入力はなし）。
  両方で変えた行は「競合」（橙）になる。トラックは DL と UP の両方にチェックが入り、サーバーの版を使って自分の版を
  「（自分の版）」という別トラックで残す。片方だけにすればその版を使う。テンポなどトラック以外の競合はどちらかを選ぶ。
  行をクリックすると何が変わったか（この PC の変更・サーバーの変更）が出て、項目をクリックするとその場所へ移る。
  サーバーは 20 秒ごとに確認し、他の人がアップすると右下にお知らせが出る（「他の人の変更を自動でダウンロード」をオンにすると、
  競合がなく再生・録音中でなければそのまま取り込む）。サーバーに新しい変更があるときにアップすると、選んだ内容で先に取り込んでからアップする。
  トラックヘッダーは、他の人の新しい変更があると色が付き「新着」、競合は「競合」、この PC の変更は「変更」と出る
- アップロード・ダウンロードは進み具合（何件目・何 MB）を表示し、「中止」できる。
  R2 への直接アップロードが失敗したら、以後はサーバー（Worker）経由で送る（同じファイルを 2 回送らない）
- トラックの追加: トラック一覧（左側の領域）やトラックの下の空き領域を右クリック →「オーディオトラックを追加」
  または「音源トラックを追加 ▶ ドラム / ベース / ピアノ」（トラック メニューからも可）
- ミキサー: F3。Cubase の MixConsole のように、ストリップごとに上から出力先（ROUTING）・インサート（外部プラグイン）・
  EQ・コンプ・センド・パン・フェーダーとメーター・M/S・番号付きの名前が並ぶ。インサートとセンドは空き枠（+）をクリックで追加、
  右クリックでメニュー。センドはバーを左右にドラッグで量。EQ・COMP 欄はクリックでそれぞれの画面を開き（マウスを乗せると枠が出る）、
  見出しの丸でオン・オフ、⇅ で EQ と Compressor のかける順番を入れ替える（欄の並びもかける順になる）。
  数値の入力: 音量はフェーダーの下の数字をクリックして dB を入力（「-6」「+3」「-inf」）、パンとセンドはダブルクリックで入力
  （パンは「L30」「C」「R20」、Alt ＋クリックで中央）。メーターは左右 2 本。下の名前をダブルクリックで名前を変更。
  左端に「入力」（オーディオ機器の入力チャンネルごとのレベルと最大値。録音前の確認用）、右端にメトロノームとマスターを固定し、
  間のトラック（コードを含む）だけが横にスクロールする（マスター音量とメトロノームはこの PC だけの設定）
- マスター（F4、またはミキサーのマスターの LIMITER / LUFS 欄をクリック）: ヴィンテージ系リミッターとラウドネスメーター。
  リミッターは THRESHOLD（下げるほど音が大きく・強くかかる）、CEILING（出力の上限。配信向けは -1.0 dB）、
  CHARACTER（0 = ゆっくりなめらか、10 = 速い）、モード ANALOG / TUBE（真空管風の倍音）/ MODERN（色付けなし）。
  ラウドネスはインテグレーテッド・ショートターム・モーメンタリー（LUFS、ITU-R BS.1770）で、目標は -14 LUFS。
  曲を再生してから「-14 LUFS に合わせる」を押すと THRESHOLD を自動で合わせる（再生を始めるたびに測り直す）。
  設定はプロジェクトに保存され全員で共通（同期パネルの「マスター」の行）。メトロノームとこの PC のマスター音量は通らない
- ミックスダウン: ファイル → ミックスダウンを書き出す（48 kHz / 24 bit WAV）。マスターのリミッターを含み、
  書き出し後にラウドネスとピークを表示する
- バストラック: ミキサーの「+ バスを追加」、またはトラックを追加 →「バストラックを追加」。トラックの出力先をバスにする
  （まとめて音量・EQ・コンプをかける）か、センドで一部を送る（リバーブ用など）。トラックの右クリック →「出力先・センド」でも設定できる
- 画面の並び（Cubase と同じ）: 上にツールバー（ツール・クオンタイズ値・スナップ・自動スクロール・メトロノーム・曲のテンポ・拍子・キー）、
  下にトランスポート（左: 左右のロケーター（旗）、中央: サイクル・停止・再生・録音、その右に現在の位置（小節. 拍. tick））。
  スナップ（Cubase と同じ →|← の形）・自動スクロール・サイクル・メトロノームはアイコンのボタン。ボタンにマウスを少し止めると説明が出る。
  オーディオ・MIDI の設定、プラグイン、サーバー設定、操作モードはメニューの「設定」。見た目は半透明のガラス風（Liquid Glass を試験的に取り入れたもの）
- タイムラインの上の段は上から 拍子・テンポ・キー・コード・マーカー。コードの段の M でコードトラックのミュート（音量はミキサーのコードのストリップ）
- ピアノロール: ノートの左端に音名（C1・D#3 など。ノートが短いときは省略）。
  ドラムのトラックでは EZ Drummer のように、行が音色ごと（キック・スネア・ハイハット…の順、名前は大きく表示）になり、
  グリッドのマスをクリックで打ち込み / もう一度クリックで消す（強さはブロックの高さで表示）
- テンポ・拍子・キー: 上のツールバーの数字をクリックして入力、ホイールで増減（再生位置のものを変える）。キーはクリックで一覧から選ぶ。
  左右のロケーター（サイクルの範囲）: 下のトランスポートの数字をクリックして「5」や「5.3.0」（小節.拍.tick）で入力、ホイールで 1 小節ずつ。
  ルーラーにも旗で表示する。テンキー 1 / 2 で左 / 右のロケーターへ移動
- コードトラック（Cubase と同じ操作）: 鉛筆でクリックすると空のコード（?）を置き、ダブルクリック（または選択して Enter）で
  コードエディターを開く。エディターは「ルート・タイプ・テンション・ベース」の 4 列と「五度圏」タブ（キーの主要なコードが明るく表示）。
  コードは置いた所で 1 回だけ鳴る（次のコードまで、最長 1 小節。長さは下の細い線）。
  選んで Ctrl+C / X、Ctrl+V で再生位置（拍に合わせる）へ貼り付け（右クリックの「ここに貼り付け」も可）。
  一括入力: コードの段を右クリック →「コードを一括入力…」で開始小節・終了小節・間隔（1 小節 / 2 拍 / 1 拍 / 2 小節ごと）を決めると
  空のコードをまとめて置く。「コード」欄に 1625 のようにディグリーの数字を並べると前から順に入る。
  コードを選んで数字 1〜7 を打つと、キー（なければ C）に合ったコードが入って次のコードへ進む（続けて 1 6 2 5 と打てる）
- トラック: ヘッダーを上下にドラッグで並べ替え、下の端をドラッグで高さを変える（段階式: 36〜288 px の 7 段。この PC の表示設定）。名前はダブルクリックで変更
- ルーラーの上では十字のカーソル（クリックで再生位置を移動）。はさみツールではクリップ・ノートの上に切る位置の縦線が出る
- キー: キートラック（拍子の下）を右クリック、または鉛筆でクリックして、小節の頭にキー（C・Am など）を置く。
  「コード進行からキーを推定して設定」もできる。ドラッグで移動、ダブルクリックで変更、Delete で削除
- ディグリー: キーを置くと、コードトラックのコード名の下にディグリー（Ⅵm7・♭Ⅶ・Ⅰ/Ⅲ など）が表示される。
  コード入力ではディグリーでも打てる（例: キー C で 6 → Am7、4 → FM7、2 → Dm7、57 → G7、b7 → Bb、1/3 → C/E。
  数字だけならキーの音階の四和音（1 → CM7、5 → G7。三和音は 6m・1maj のように書く。分数コードは三和音）。
  ローマ数字 IV・vi7 も可）。入力画面の「ディグリー」の段はキーの四和音のボタン
- マーカー: マーカートラック（ルーラーの下）に鉛筆で追加、Insert で再生位置に追加。左から 1, 2, 3 … と番号が付き、
  Shift + 数字キーでジャンプ。ダブルクリックで名前、ドラッグで移動、Delete で削除
- MIDI ファイル: タイムラインにドラッグ＆ドロップ（またはファイル → MIDI ファイルを読み込む）。パートごとにトラックを作り、
  チャンネル 10 はドラム、ベース・エレピの音色はそれぞれの内蔵音源にする。空のプロジェクトならテンポ・拍子も取り込む
- MIDI キーボード: 設定 → オーディオ・MIDI の設定の「MIDI キーボード」で機器をオン・オフ（弾くとバーが動く）。
  MIDI トラックの録音待機ボタン（●）をオンにすると、そのトラックの音源で鳴り、録音（* / テンキー *）で MIDI クリップになる
  （録音待機の MIDI トラックがなければ選択中の MIDI トラック）
- トラックヘッダーの音量・パンは、スライダーの横に数字で出る（クリックして入力: 「-6」「L30」など）
- 内蔵音源: ドラム / ベース / ピアノ / エレピ（柔らかい音色と明るめの音色）。
  音源は版ごとに固定される（共同作業の相手と同じ音にするため）。新しい版が出たら音源の設定画面の「新しい版 … に更新」で切り替える。
  ドラムのピアノロールは、キットにある音だけを明るい行で表示する。キットにない GM の音は「（音なし）」と暗く出し、
  そこに置いたノートは斜線付きで薄く表示する（鳴らない）。ドラム 1.1.0 で GM 35（キック 2）・55（スプラッシュ）・59（ライド 2）を追加
- クオンタイズ値: ツールバー（またはピアノロール）で Cubase と同じ一覧から選ぶ
  （1/1〜1/128、1/2〜1/32 の 3連符、1/4〜1/16 の 5連符・7連符）。
  タイムラインとピアノロールのグリッド線もこの値の細かさで表示する（細かすぎるときは間引く）。
  ノートの配置・クオンタイズ・ルーラーでの再生位置の移動がこの値に合う。J でスナップのオン／オフ（フリー）、Alt で一時的にフリー
- 自動スクロール: F で切り替え（再生中にタイムラインとピアノロールが再生位置を追う）
- EQ / Compressor: すべてのトラックに標準で付いている。EQ と Compressor は別々の画面で、ミキサーの EQ・COMP 欄をクリック、
  またはトラックの右クリック →「EQ…」「Compressor…」で開く。かける順番は画面上の「EQ → Comp」ボタン（またはミキサーの ⇅）で入れ替える。
  EQ はグラフで操作する（再生中はそのトラックのスペクトラムをなめらかな曲線で表示。1 kHz を中心に 4.5 dB/oct 傾けて表示）。
  点をドラッグで周波数とゲイン、ホイールで Q、ダブルクリックでリセット。バンドはローカット・Low（シェルフ）・Low Mid・Mid（ピーキング）・High（シェルフ）・ハイカット。
  Compressor は FET（1176 風の画面: INPUT・OUTPUT・ATTACK・RELEASE・レシオ 4/8/12/20）と
  Optical（LA-2A 風の画面: GAIN・PEAK REDUCTION・COMPRESS/LIMIT）。どちらにも LOW THRU（この周波数より下の音ではかかり具合を決めない。
  OFF〜500 Hz。ベースやキックで必要以上にかからないように）がある。ゲインリダクションは VU メーターの針で表示する。
  バウンスには含めない（受け取った側でも同じ設定がかかる）

主なショートカット: Space 再生/停止、テンキー 0 停止、* / テンキー * 録音、Home / テンキー . 先頭へ、
テンキー 1 / 2 左 / 右のロケーターへ、L / テンキー / サイクル、P 選択範囲をサイクルの範囲に、G / H ズームアウト / イン、J スナップ、F 自動スクロール、
Insert マーカーを追加、Shift + 1〜9 マーカーへ移動、1 / 2 選択・鉛筆ツール、
C メトロノーム、Q クオンタイズ、Alt+X 分割、M / S 選択中のトラックのミュート / ソロ、F3 ミキサー、Ctrl/Cmd+S 保存、Ctrl/Cmd+Z 元に戻す、Ctrl/Cmd+D クリップ複製、Delete 削除。

### アップデート

アプリは手元に置いたまま新しくできる（ヘルプ → アップデートを確認…。CI でビルドしたアプリは起動時にも確認する）。
更新は同期サーバーから配信され、変わったファイルだけをダウンロードして置き換える（Windows は exe のフォルダ、Mac は .app の中身）。
同期サーバーの URL とトークンを設定しておく必要がある。

配信のしかた:
1. 最初に一度だけ、推測されにくい文字列（リリースキー）を決めて、次の 2 か所に同じ値を登録する（チャットなどには書かない）
   - Cloudflare: Worker の「設定 → 変数とシークレット」にシークレット `RELEASE_KEY`
   - GitHub: リポジトリの Settings → Secrets and variables → Actions に `SHAREDAW_RELEASE_KEY`、
     あわせて `SHAREDAW_SERVER_URL`（同期サーバーの URL）
2. Actions → Build → Run workflow（「配信する」にチェック）。ビルドが終わると各 OS のアプリにアップデートが届く
   （ビルド番号 = Actions の実行番号で新旧を判断する）。配信は別の軽いジョブ（publish）なので、
   配信だけ失敗したときは「Re-run failed jobs」でビルドをやり直さずに再実行できる
3. 100MB を超えるファイル（Mac 版の本体など）を送るには、Worker に R2 の API キーを設定しておく（server/README.md）

最初の 1 回だけは、これまでどおり Artifacts からアプリを手で入れる（アップデート機能を含むビルドにするため）。

## ビルド

必要なもの: CMake 3.22 以上、C++20 コンパイラ（Windows は Visual Studio 2022）、Git。

```bash
git clone <このリポジトリ>
cd sharedaw
# Tracktion Engine の .gitmodules は JUCE を SSH の URL で参照しているため、HTTPS で取る場合は読み替える
git config --global url."https://github.com/".insteadOf "git@github.com:"
git submodule update --init --recursive

# Windows
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release

# macOS（Universal Binary）
cmake -S . -B build -G Xcode -DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"
cmake --build build --config Release
```

成果物は `build/app/ShareDAW_artefacts/Release/` にできる（内蔵音源の `assets` フォルダも隣にコピーされる。
Mac はアプリの `Contents/Resources/assets`）。

単体テストだけなら JUCE なしでビルドできる:

```bash
cmake -S . -B build-core -DCOLLAB_BUILD_APP=OFF
cmake --build build-core
ctest --test-dir build-core --output-on-failure
```

Windows で ASIO を使う場合は Steinberg の ASIO SDK を用意し、`-DCOLLAB_ASIO_SDK_DIR=<SDKのフォルダ>` を付けて
構成する（付けない場合は WASAPI のみ）。CI は SDK を Steinberg のサイトから取得できたときだけ ASIO を有効にする
（ジョブの警告に出る）。ASIO SDK は Steinberg のライセンスに従うこと。

## CI

GitHub Actions（`.github/workflows/build.yml`）で Windows / macOS（Universal）/ Linux をビルドし、
単体テストと、Linux ではデモプロジェクトの書き出しと、テスト用プラグイン（`tools/test-plugins`）での
スキャン・バウンスのスモークテスト（`tools/plugin-smoke-test.sh`）を行う。ビルド済みのアプリは
各ジョブの Artifacts からダウンロードできる。
ビルドは全 OS で Ninja ＋ コンパイラキャッシュ（ccache、Windows は sccache）を使うので、2 回目以降は変更したファイルだけを
コンパイルする（最初の 1 回と、JUCE / Tracktion を更新したときは時間がかかる）。手動実行（Run workflow）で `mac_universal` を
オフにすると、Mac は Apple Silicon だけをビルドして時間がほぼ半分になる。シークレットを設定していれば、同期サーバーへの配信
（`tools/publish-release.mjs`、上の「アップデート」）も行う。

## 初回起動（署名なしの配布物）

Apple Developer には登録していないので、Mac 版は公証なしのアドホック署名、Windows 版は署名なしで配布する。

- **Mac**:
  1. `ShareDAW.dmg` を開き、`ShareDAW.app` を「アプリケーション」フォルダへドラッグする。
  2. 一度アプリを開こうとする（「開けません」と表示されるので「完了」で閉じる）。
  3. 「システム設定 → プライバシーとセキュリティ」の下のほうにある「このまま開く」を押し、確認でもう一度「このまま開く」。
     - macOS 14 以前は、Finder でアプリを右クリック →「開く」でもよい。
     - ターミナルで `xattr -dr com.apple.quarantine /Applications/ShareDAW.app` を実行しても開けるようになる。
  4. 録音するときにマイクの許可を求められたら「許可」する。新しいビルドに入れ替えたときは、もう一度聞かれることがある
     （アドホック署名はビルドごとに変わるため）。聞かれずに無音で録音される場合は「システム設定 → プライバシーとセキュリティ →
     マイク」で ShareDAW をオンにする。
- **Windows**: 署名していないため SmartScreen の警告が出る。「詳細情報」→「実行」で起動する。
